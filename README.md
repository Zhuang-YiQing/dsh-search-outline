# dsh-search-outline

DSH（DeepSeek Harness）右栏的 **文件预览增强**插件：给 better-sidebar 的文件预览**叠加**一层查找条、符号大纲
和右键菜单 —— 文件本体仍然由 better-sidebar 自己的查看器渲染与编辑，本插件不替换它。

**没有独立 tab**：不注册「搜索」页，也没有「搜索视图」页 —— 打开文件就是这套界面。

被叠加回来的宿主能力（本插件不再顶掉它们）：右栏**编辑与保存**（含冲突提示）、Markdown / HTML / JSONL 的
**渲染 ⇄ 编辑切换**、Markdown 的**图片相对路径与链接认领**、标题锚点、git gutter、超大文件分页预览、
preview / edit 的滚动位置记忆，以及 better-sidebar 自带的「选区加入对话」浮窗。

## 功能一览

| 能力 | 是什么 | 怎么用 |
| --- | --- | --- |
| 🔍 **漂浮查找条** | 字面量 / 正则 / 区分大小写；全部命中高亮、当前命中加深、`n/m` 计数、上下跳 | 平时只是左上角一个「查找」小泡泡，点它或按 `Ctrl+F` 才**在宿主视图上盖一层只读高亮浮层**（宿主的编辑器 / 预览仍挂在底下，未保存的改动与滚动位置都留着）；`Enter` / `Shift+Enter` 跳下一条 / 上一条，`↑` `↓` 同义；`×` 或 `Esc` 关掉浮层即回到宿主的预览 / 编辑器。查找条**悬浮**，只在展开时盖住顶上一条，不占用内容区 |
| 🧭 **右侧「结构」面板** | IDEA Structure 风格的符号大纲：Java / JS / TS / Python 给**类 / 方法 / 变量**（变量只取文件级：Java 类字段、Python 模块变量、JS 顶层变量，方法内局部变量不列）；HTML（`.html/.htm/.xhtml/.vue/.svelte`）给**元素**大纲（结构标签 + 带 `id`/`class` 的标签，形如 `div#app.container`）；Markdown 给**标题**大纲（按层级缩进，代码围栏和 YAML front matter 里的不算） | 停靠在预览区右侧，内容区自动让出 210px，**不覆盖正文**；类 / 方法 / 变量三类一直一起显示，类节点下挂成员可折叠；点条目在**宿主视图里定位**（编辑器按行号 gutter，渲染预览按标题）并闪烁 1.6 秒，实在定位不到才盖上我们的查找浮层；顶部按名称筛选；右上 `›` 收起成 24px 窄条；标题栏排序按钮循环「位置 / 类型 / 名称」 |
| 📑 **Markdown / HTML 渲染预览** | 由 better-sidebar 的内置查看器负责：`.md` 打开即渲染（GFM 表格、代码块、任务列表、图片、可点的本地链接、标题锚点），`.html` 走它的沙箱渲染，随时可切回编辑并保存 | 本插件不再自己渲染，只在渲染结果上**叠加**查找条 / 大纲 / 右键菜单；切换渲染 ⇄ 编辑用宿主自己的表头按钮 |
| ✍️ **选中即加入对话** | 选中一段（可跨行）→ 右键 →「添加到对话」：以引用 chip 追加进当前会话输入框，标签是 `路径:行号`，发送时展开成带围栏的代码块（和 better-sidebar 自带的「加入对话」同一个形态） | 右键菜单另一项是「复制选区」（只复制选中文本，不带行号和围栏）；在宿主的编辑器 / 渲染预览里拿不到源码行号时，按选区文本回查（全文唯一出现才带行号）；宿主自带的「添加到对话」浮窗也还在，两者并存 |

覆盖范围：代码、配置、Markdown、日志、CSV、无扩展名文件…… 只要 better-sidebar 的内置查看器
（`markdown` / `html` / `jsonl` / `code` catch-all）能接手这个扩展名，我们就在它上面叠加；
图片 / PDF / Office 等二进制不碰；用户关掉某个内置查看器时，只有它兜底的扩展名会一并让开（不再认领）。

## 和 code-nav 的关系

| | code-nav | 本插件 |
| --- | --- | --- |
| 接管方式 | 自己渲染文件本体，顶掉内置查看器 | **叠加**在内置查看器上，文件本体仍由宿主渲染 |
| 接管范围 | 代码 + 常见配置扩展名 | 内置查看器能接手的所有文本扩展名（含 `.md/.txt/.log/.css/.html`、无扩展名） |
| 查找 | 常驻查找框（无 Ctrl+F、无正则） | 漂浮查找条 + **Ctrl+F** + **正则**（按需盖上只读高亮浮层） |
| 符号 | 多语言（下拉列表） | Java / JS / TS / Python（右侧结构树）+ HTML 元素 / Markdown 标题 |
| Markdown 渲染 | ✗（还是源码编辑器） | ✓ 交回 better-sidebar 的内置渲染（图片、链接、锚点都在） |
| 选区入对话 | ✗ | ✓ 右键 →「添加到对话」（引用 chip，带 `路径:行号`），宿主的自带浮窗并存 |
| 编辑 / 保存 | ✗ 只读 | ✓ 交回宿主，右栏照常编辑、保存、看冲突提示 |

两者注册的是同类预览器，本插件优先级更高（50 > 10），所以**同时装也只会有本插件生效**。
装了 code-nav 的话建议在 better-sidebar 设置 →「侧边卡片」→「文件预览」里把「代码预览导航」那张卡片关掉，
免得占着开关位看不清谁在生效。反过来，把本插件的「大纲预览」关掉就能完全回到 code-nav / 内置查看器。

## 安装

前置：DSH Desktop（或 `dsh web`）已在跑，profile 名为 `desktop`，且已装 **dsh-better-sidebar**
（本插件的预览器挂在他的 `ctx.betterSidebar` 服务上，没有它时插件静默不生效）。

### 方式 0：从 GitHub 克隆（推荐）

```powershell
git clone git@github.com:Zhuang-YiQing/dsh-search-outline.git D:/dsh/myplugin/dsh-search-outline
cd D:/dsh/myplugin/dsh-search-outline
pwsh -File scripts/install.ps1
```

### 方式 A：脚本（推荐，幂等）

```powershell
pwsh -File scripts/install.ps1                          # 默认 desktop
pwsh -File scripts/install.ps1 -ProfileName web         # 或指定 profile
```

脚本从 `package.json` 读包名，只做两件事：在 `<profile>/node_modules` 建一个指向本仓库的目录联接，
在 `<profile>/cordis.patch.yml` 追加一段带标记的挂载行。**不改** `package.json` / `pnpm-lock.yaml`。
撤销：`pwsh -File scripts/uninstall.ps1`。

装完**必须重启 DSH**（宿主半要重新加载），然后浏览器硬刷新（Ctrl+Shift+R）。

### 方式 B：官方 CLI

```powershell
dsh plugin --profile desktop add link:D:/dsh/myplugin/dsh-search-outline
```

走这条通道时**不要**再用方式 A 的挂载行（插件自带的 `dsh.bundle.patch` 会挂载，双挂载会报重复 id）。

### 方式 C：手动

1. 建目录联接（同方式 A 的第一步，目录名用 `dsh-search-outline`）；
2. 编辑 `~/.dsh/profiles/desktop/package.json`：`dependencies` 加
   `"dsh-search-outline": "link:D:/dsh/myplugin/dsh-search-outline"`，`dsh.profile.bundles` 末尾加 `"dsh-search-outline"`；
3. 在 profile 目录跑一次 `pnpm install`；
4. 重启 DSH，硬刷新浏览器。

## 使用

1. 右栏「文件」树里点开任意文件（或从聊天里的文件链接打开）：内容区**还是 better-sidebar 自己的**预览 / 编辑器
   （Markdown 打开即渲染，链接可点，随时切回编辑），只是右侧多一个「结构」面板、左上多一个「查找」泡泡；
2. 需要逐字符高亮时点「查找」泡泡或按 `Ctrl+F` → 在宿主视图上**盖一层我们自己的只读高亮浮层**
   （文件名 + 输入框 + `n/m` + `Aa` + `.*` + ↑ ↓ + `×`）；`×` 或 `Esc` 关掉浮层即回到宿主的预览 / 编辑器，
   底下那层宿主视图一直挂着，所以未保存的编辑和滚动位置都不会丢；
3. 编辑与保存照旧：退出查找浮层就是宿主的编辑器，改完照常保存，mtime 冲突提示也在；
4. 键盘：查找框内 `Enter` / `Shift+Enter` 上下跳，`↑` `↓` 同义；`F3` / `Shift+F3` 在内容区也能跳下一条 / 上一条
   （会自动打开查找浮层）；`Esc` 先关查找浮层，再清查找词；
5. 结构面板：类行可折叠（`▸/▾`），点类或成员 → 在宿主视图里定位（编辑器按行号 gutter，渲染预览按标题）并闪烁 1.6 秒，
   定位不到才盖上我们的查找浮层；Markdown 标题按层级缩进；
   顶部输入框按名称筛选；右上 `›` 收起成窄条，点窄条 `‹` 重新展开。
6. 结构面板标题栏的排序按钮可在三种模式间循环（与筛选叠加）：
   - **位置**（默认）：源码顺序，类下挂成员；
   - **类型**：分成「标题 / 类 / 方法 / 变量 / 元素」几段（HTML 只有「元素」，Markdown 只有「标题」），段内按行号；
     每个段标题左侧的 `▾/▸` 可以单独展开 / 收起该段（默认展开，`结构 (N)` 只统计当前可见行）；
   - **名称**：类与成员都按名称字母序。

### 把选区加进对话

1. 在内容区**拖选**要用的片段（可以跨行；编辑器里选行时行号列不会被带进去）；
2. 在选区上**右键** → 菜单顶部显示这次的 `路径:起-止`，下面两项：
   - **添加到对话**：把选区追加到当前会话输入框的**末尾**（草稿已有内容时自动补一个空格）；
   - **复制选区**：只复制选中的文本，不带行号和围栏。
3. 插入成功后底部会闪一条「已添加到对话输入框」提示。

在宿主的编辑器 / 渲染预览里选中文本没有源码行号，所以先按选区文本回查源码行
（全文唯一出现才给行号），回查不到就只插「`路径`」标签 + 选中的文本。
只有在我们自己的查找浮层里才能直接拿到行号（每行都标了行号）。

插入形态与 better-sidebar 自带的「加入对话」一致：输入框里是一个引用 chip，
标签是 `src/a.js:12-15`，发送时展开为带围栏的代码块：

````text
```src/a.js:12-15
…选中的源码…
```
````

行为细节：

| 情况 | 结果 |
| --- | --- |
| 选区超过 4000 字符 | 只插「`路径:起-止`」这一行位置标签（菜单项会显示「仅位置」），避免把整份文件灌进草稿 |
| 宿主没有引用 chip 通道 | 自动退化成纯文本（同样的围栏内容），提示会写明「（文本）」 |
| 输入框里已经挂了 chip | 走宿主的插入通道，不会把已有 chip 拍平成文本 |
| 正在发送消息 | 拒绝插入并提示「正在发送，稍后再试」 |

> 插入位置固定在**草稿末尾**：宿主 composer 没有暴露 caret API，无法插到光标处。

## 开关与回退

预览器在 better-sidebar 设置页 **「侧边卡片」→「文件预览」→「大纲预览」** 里有独立开关：

- 关掉它 → 叠加层完全消失，文件回到 better-sidebar 原样（内置的 Markdown 渲染预览、可编辑编辑器、自带选区浮窗都在）；
- 关掉某个**内置**查看器（比如「代码」catch-all）→ 只有它兜底的扩展名我们会一并让开，不去接管宿主已经不再渲染的那些文件；
- 查找浮层只在按 `Ctrl+F` 或点「查找」时出现，平时不占界面；渲染 ⇄ 编辑切换用宿主自己的表头按钮。

> 本插件不拦截编辑：文件本体是宿主的编辑器，改和保存都走宿主。只有查找浮层那一层是只读的。

## 已知边界

- 结构面板是**逐行启发式解析**（不是编译器精度），只覆盖 Java / JS / TS / Python / HTML / Markdown；
  HTML 给元素级大纲（结构标签 + 带 `id`/`class` 的标签），内联 `<script>` 里的 JS 额外展开为方法 / 变量，
  行号与原文一一对应；
  Java 支持注解、多行参数列表、带空格的泛型返回类型；变量只取类级字段（方法内局部变量不列）；
  Markdown 标题跳过代码围栏（```` ``` ```` / `~~~`）与 YAML front matter，支持 ATX 与 setext 两种写法；
- **查找浮层是只读快照**：它盖在宿主视图上，进去之后不会跟着宿主的编辑实时更新，退出再进就是新内容；
  宿主视图始终挂载，所以浮层开着时未保存的改动也还在（关掉浮层就能看到）；
  `Ctrl+F` 被本插件接管（进查找浮层），CodeMirror 自带的搜索仍可用（走它自己的快捷键）；
- 委托状态下结构跳转靠**只读 DOM** 定位（编辑器的行号 gutter、渲染预览里的标题元素）：行号列被关掉、
  长行折行时可能落到近似位置，定位不到会盖上我们自己的查找浮层；不改宿主编辑器内部、不发编辑事务；
- 第三方插件的查看器（id 带冒号，例如 code-nav）**不会被委托**：我们优先级更高时它会被这层叠加顶掉，
  请在「侧边卡片」→「文件预览」里关掉那张卡片；反过来关掉「大纲预览」就完全交还给它们；
- 我们只委托 `fsRead` / `none` 读取策略的内置查看器，非 `fsRead` 的扩展名不认领（我们拿不到它的内容）；
- 超大文件（宿主不再返回全文，改走自己的分页预览）：结构与高亮查找不可用，界面会写明，
  请在编辑器里用 CodeMirror 自带的搜索；普通文件的读取上限由宿主决定（约 500KB），超出部分不参与查找；
- 超过 1200 行时查找浮层默认只渲染当前命中附近，可点「显示全文」；单次查找最多统计 20000 处命中；
- 二进制文件（含 NUL 字节）在查找浮层里显示提示，不渲染；
- 「添加到对话」只能追加到**草稿末尾**（宿主未暴露 caret API）；选区上限 4000 字符，超过只放位置标签；
- 宿主半 `lib/index.js` 的工作区搜索接口（`/api/code-search/*`）目前**保留但未使用**，
  供以后做「文件名/内容全局搜索」时复用；它仅接受回环请求，路径经 realpath 校验限制在会话工作区内。

## 目录结构

```
lib/client.js   浏览器半：文件预览**叠加层**（查找条 + 右侧结构面板 + 右键菜单，文件本体交回宿主内置查看器），手写 ModuleLoader bundle
lib/index.js    宿主半：/api/code-search/*（当前未使用，保留）
lib/search.js   宿主半检索核心（当前未使用，保留）
scripts/        install.ps1 / uninstall.ps1（包名自动取自 package.json，幂等）
test/           单测：浏览器半 53 项 + 宿主 16 项（search 8 / plugin 8）
```
